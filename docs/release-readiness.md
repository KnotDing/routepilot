# 正式发布准备与验收

## 当前判断

2026-10-09，在 v0.5.2 源码基础上扩充回归测试，作为 v0.5.3 的发布准备。此记录描述本机检查范围和结果，远端发布以 Gitea 工作流及 Release 资产为准。

自动化验证覆盖面已扩大，但 **1.0.0 仍需完成下方真实部署验收**。临时数据库、模拟进程和回环网络通过，不能证明真实 PF、网关或 root LaunchDaemon 升级已经验收。

## 可重复执行的检查

需要 macOS Apple Silicon、Xcode Command Line Tools、满足 go.mod 的 Go、Node.js 22.12+、npm、Python 3，以及可运行 AppKit/WKWebView 的已登录图形会话。Runner 应使用普通用户；这些检查不需要 sudo。

```sh
npm --prefix web ci
npm --prefix web exec -- playwright install chromium
make verify-release
make coverage
make fuzz
```

`verify-release` 按顺序执行前端测试、全部 Go 竞态测试、go vet、前后端构建、原生检查、浏览器检查、完整 App/DMG/ZIP 打包及校验。每次实际执行 Go 测试，不使用旧的成功缓存。构建会清理历史发布产物，保留 UI 检查截图；不要同时运行多个构建命令。

可单独运行：

| 命令 | 范围 / 前提 |
| --- | --- |
| `make frontend-test` | React 页面、操作流程、英文覆盖和 Markdown |
| `make test` | 全部 Go 包、集成测试及数据竞态检测 |
| `make native-test` | 原生逻辑、私有凭证目录、安装资源、真实 WKWebView；先运行 `make frontend` |
| `make ui-test` | Chromium 中的固定 API 样本；先运行 `make frontend` |
| `make coverage` | 不缓存的竞态测试及语句覆盖报告 |
| `make fuzz` | 稳定版本解析的 5 秒模糊测试 |
| `make package-check` | 已构建安装包的只读完整性检查；先运行 `make package` |

测试使用临时目录、临时数据库、模拟 Surge、回环 TCP/UDP/HTTP，以及独立原生测试窗口；不更改正在运行的 RoutePilot 服务、真实 PF、Surge 配置或钥匙链。原生窗口检查验证任务完成标记，防止异步检查尚未执行就误判成功。

浏览器通过锁定版本的 Playwright 运行，默认从 `web/node_modules/playwright` 加载；仍可用 `PLAYWRIGHT_MODULE` 指定模块路径。`ui_remote_check.cjs`、`ui_cache_live_check.cjs` 等针对特定运行中后台的旧脚本不属于离线发布门禁，需要另行准备隔离后台才能运行。

本轮 Go 总语句覆盖率为 58.2%；事件 100%、通知 94.4%、缓存 90.8%、分类器 92.9%、App 73.2%、凭证与认证 59.8%、升级 32.2%。总覆盖率仍有提升空间，尤其是权限受限的系统安装、CLI 入口和部分管理 API。

重复测试还修正了原有 BGP 检查的异步时序：门禁关闭后等待撤路由及状态快照完成，同时持续断言独立手动路由没有丢失。固定 DNS 源端口改为测试独立分配，两个进程各连续运行 20 轮通过。后台打包排除 macOS 的 Finder 元数据副文件，并用错误包回归测试验证校验脚本确实拒绝附加可执行文件、重复路径与损坏 gzip 尾部。

本轮带竞态检测的 UDP 检查约 70,709 QPS、P50 0.207 ms、P99 0.743 ms。它只衡量回环 UDP 与分类/响应缓存，不包含真实上游、PF、网关或 Surge 延迟；不能作为真实部署吞吐承诺。

### 新增回归范围

- 在线升级：稳定版本比较、错误/重复资源、下载来源与跳转、大小限制、校验和、压缩包截断/CRC/非规范路径；检查请求合并、快速返回、重复提交、失败状态、进程就绪、替换失败与回滚失败。
- 凭证：更新前后保留原会话过期时间；拒绝过期、配置不符、未来时间、超量和畸形凭证；本地保存隔离、0700/0600 权限、软链接/硬链接/损坏文件；测试不访问真实钥匙链。
- 通知与事件：错误选择、冷却、恢复、队列饱和、配置变化丢弃旧任务、Webhook 重试/重定向拒绝/日志脱敏；慢订阅者淘汰、订阅上限和并发退订。
- 缓存与统计：真实临时数据库的多次关闭/重开；无关配置保存、AAAA 热更新和 DNS 重建不清空有效决策；手动删除持久化；恢复保留原 TTL、待刷新标记、LRU 和当前进程新值；拒绝不匹配条目。
- AAAA 回落：优先于 Hosts 与 always-real-ip；仅 IPv6 已确认关闭且策略启用时生效；NODATA / EDNS；热更新、不影响 A；上游失败或返回 Fake-IP 时不改走 Surge。
- 更新界面：最新版本隐藏横幅、按后端跳过版本、稍后/Escape、仅一次提交、重启轮询和认证失败；安全渲染 Markdown；原生失败提示和三按钮返回值。
- 状态栏：每个包固定走一个分支；按 DIRECT / SURGE 比例随机抽样；统计更新不改道、零统计及异常输入；18×18 模板图。

覆盖率只是缺口定位工具。升级模块包含 root 目录、launchctl、安装助手等未直接执行的路径；本轮通过的是临时目录和模拟 launchd/PID 的替换与回滚核心，不能称为真实远程升级成功。

### 报告位置

- `.cache/release-coverage.out`：Go 语句覆盖数据。
- `.cache/release-tests.log` / `.cache/verify-release.log`：完整竞态测试与发布门禁日志。
- `.cache/native-tests/ui.log`：真实 WKWebView 测试结果。
- `artifacts/ui-forms/verification.json` 与同目录 PNG：页面检查及截图。
- `artifacts/package-verification.json`：当前安装包版本、校验和与检查范围。
- `artifacts/SHA256SUMS`：发布用的 DMG 和 ZIP 校验和。

构建会删除旧的安装包成功报告；任何校验失败都返回非零，工作流不会继续发布。签名检查验证包未损坏；目前仍使用 ad-hoc 签名，不代表 Developer ID 签名、公证或 Gatekeeper 首次打开验收。

## Gitea 门禁

`.gitea/workflows/test.yaml` 在 main 推送与 PR 时运行回归、原生/页面检查和模糊测试；`.gitea/workflows/release.yaml` 在版本标签推送后先完成全部检查与安装包校验，再创建 Release 和上传 DMG、ZIP 和 SHA256SUMS 三项资产。两者均使用 `macos-arm64` Runner。

本机记录不等于远端 Actions 的执行结果；推送提交和标签后需要确认两个工作流均通过，且 Release 的三项资产上传完成。图形会话或工具缺失会直接失败，应修复 Runner 条件，不应绕过门禁。

## 1.0.0 前仍需真实环境验收

| 项目 | 验收要求 | 当前证据 |
| --- | --- | --- |
| IPv4 / IPv6 透明 DNS | 真实 PF 接收、原目的地址、固定出口；独立网关抓包确认 WAN 不绕行；无自转发循环 | 规则生成和回环协议检查通过；真实链路待验收 |
| BGP | 独立对端验证建邻前/后新增、删除、IPv4/IPv6、重复提交、断线重连的 RIB/FIB 与下一跳 | 自动化本地 GoBGP 测试通过；部署验收待完成 |
| App / 本机升级 | 从实际旧版升级；配置、数据库、会话、本地凭证保留；已配置助手后免重复管理员授权；失败恢复 | 核心和安装包检查通过；真实权限/助手链路待验收 |
| 远程后台升级 | 浏览器/App 登录后升级实际标准后台；断线恢复、版本一致；错包、下载中断、新进程失败时可恢复并显示失败原因 | API/UI 和模拟替换/回滚通过；真实 LaunchDaemon 待验收 |
| 实际通知 | Surge / BGP / DNS 异常、恢复与错误筛选；App 系统通知及远程 Webhook，无重复风暴 | 模拟健康及回环 Webhook 通过；系统权限与远程链路待验收 |
| 长期运行 | 建议至少 72 小时，涵盖休眠唤醒、网络切换、Surge 停启、上游故障、规则自动更新、并发保存；跟踪内存/FD/任务与缓存 | 短时竞态和负载通过；长期部署记录待完成 |
| 首次安装 | 干净用户首次打开、首次授权、卸载保留数据、从发布 DMG 安装后重开及窗口恢复 | 构建资源检查通过；人工首次安装体验待完成 |

实施真实验收前应备份配置和数据库，选定可恢复的维护时间及测试网关。以上项目应记录系统/Surge/网关版本、安装方式、App/后台版本、输入操作、期望/实际结果、日志或抓包、恢复结果及验收日期。全部完成且没有未解决的阻塞问题，再决定发布 1.0.0；否则继续使用 0.x。
