# 缓存与 DNS 请求量告警

在“设置 → 通知”选择“缓存不一致率过高”“突发大量 DNS 请求”“长时间大量 DNS 请求”，
并在下方调整阈值。通知总开关、恢复通知、重复提醒间隔及现有系统通知 / 浏览器通知 / Webhook
选择继续生效。旧配置未选择具体事件时沿用 DNS 类别选择；已明确选择事件的配置不会自动增加新事件。

| 告警 | 默认条件 |
| --- | --- |
| 缓存不一致率过高 | 采样窗口 60 秒，至少 100 个已核对请求，不一致率达到 5% |
| 突发大量 DNS 请求 | 最近 10 秒的平均请求速率达到 500 请求/秒 |
| 长时间大量 DNS 请求 | 每次采样的请求速率均达到 100 请求/秒，连续至少 300 秒 |

后台每秒独立采样，页面关闭后仍检测并通过已配置的 Webhook 推送。App 系统通知在状态栏菜单的「应用偏好 → 本机通知设置」中启用并允许通知权限，
可在管理窗口关闭后继续观察本机和已登录的远程后端；浏览器通知需要保持页面打开。
告警只用于通知，不参与健康门禁，不切换 DNS 分流、路由或触发 Surge 自动重启。
阈值保存后热应用，不重建 DNS / BGP 运行组件。

缓存分别检查乐观决策缓存和乐观响应缓存，两者使用同一个可调整的阈值，不合并分母。响应计数涵盖全局上游、策略专用解析池和 Surge 响应缓存池。
分母为窗口内新增的已核对请求数，分子为其中不一致的请求数。未核对、刷新失败和仅后台空闲刷新
不补算成一致；未启用相应乐观缓存时不检测该项。采满窗口且达到最小样本量后才判定，
样本不足或采样中断为未知，不发送恢复通知。手动清理缓存后重新建立核对基线。

请求量使用当前后端累计 DNS 查询数的新增量及实际经过的时间，不使用客户端数量或每分钟展示值推算。
突发告警使用覆盖完整窗口的平均速率；持续告警要求每次采样都达到阈值，低于阈值即重新计时。
进程重启、计数回退、系统暂停造成超过 5 秒的采样间隔、时钟回退或阈值变更后重新采样。
不会把持久化恢复的累计数当作启动流量。窗口边界按实际采样点计算，通知详情显示实际覆盖秒数。

现有重复提醒间隔为 0 时，同一持续异常不重复提醒；恢复后再次异常可以重新提醒。
非零间隔允许持续异常按冷却时间重复提醒，仍以所选事件及恢复开关为准。

只读状态接口增加可选的 `notification_anomaly_alerts` 能力标记及 `notification_alerts` 数组。
告警的稳定名称、状态与数值详情与健康状态分开，`UNKNOWN` 不伪装为正常。复用已有 `status` 接口，
本地、CLI 与远端中继无需新增路径。旧后端隐藏不支持的事件，保留已有通知设置并提示升级。
Webhook 保持 `title`、`body`、`state`、`components`、`at`，新增可选 `details` 显示速率、
阈值或缓存核对比例；详情仅来自统计数值，不包含凭据、客户端 IP 或域名。

检测窗口和持续时间为本进程状态，重启后重新采样；原始累计缓存可靠性计数仍按既有规则持久化。
