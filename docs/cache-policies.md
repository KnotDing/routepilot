# 按决策与上游控制乐观缓存

在「设置 → 缓存」中，乐观决策缓存与乐观响应缓存分别显示为带总开关的分组框。勾选总开关后展开空闲刷新和对应的分项开关，取消后收起内容但保留分项设置。宽屏并排，窄屏上下排列。设置作用于当前连接的后端，沿用先校验并保存、再后台应用的流程；以应用状态确认是否生效。旧后端缺少能力标记时显示升级提示，不展示不可用的分项开关。

## 决策与开关

DIRECT、SURGE、REJECT 每项仅提供一个乐观缓存开关。勾选后允许配置变化时保留旧决策并在后台刷新；关闭后确认配置变化时移除该项旧决策，等待同步求值。有效普通缓存仍按原来的 TTL、长期保留和策略组选择失效设置工作。

UNKNOWN 与求值失败沿用短期普通缓存及原有 TTL，不提供乐观缓存开关，也不会持久化。

未设置分项时继承原行为，旧配置无需迁移。分项不能绕过总开关；关闭总开关后保留分项配置，便于重新开启。

## 上游与开关

按实际返回响应的上游设置。UDP/TCP 使用 `协议://IP:端口`，DoH 再追加 `|HTTPS URL`，DoT 再追加 `|TLS 服务器名称`，避免同一 IP 上不同服务混为一项。同一上游在全局真实 DNS、策略主上游与备用上游中共享开关，缓存内容仍按各解析池与完整查询分区隔离。上游轮询和失败回退顺序保持原行为。

每个上游只提供乐观缓存开关。关闭时，保留 TTL 内的普通响应及原到期时间；过期响应不返回、不恢复、不进行空闲刷新。确认 Surge 配置变化后也不会保留该上游的旧响应。只持久化允许乐观保留的响应。

开启保留原始目标时，已观察到的原始 DNS 上游会出现在列表中，也可单独设置。尚未设置的原始上游继承总开关。删除上游配置不会移除其分项开关和历史可靠性计数。

配置字段位于 `settings.cache.decisions` 与 `settings.cache.upstreams`，值为包含可选布尔字段 `optimistic` 的对象。省略字段表示继承默认；显式 `false` 经保存、备份、恢复与配置克隆后仍有效。

## 分项统计

决策缓存页与 DNS 查询页的可靠性卡片分别显示各决策、各上游的条目、命中、未命中、淘汰、待刷新、旧值命中、已核对、不一致和不一致率。

- 条目和待刷新为当前快照。命中、未命中、淘汰属于当前缓存实例，实例重建后重新计数。分项未命中在前台查询获得实际结果后归属；无法确定结果的失败或取消仅计入总未命中，不虚构上游归属。
- 乐观统计按请求计数：同一个旧值被返回四次后，一次成功刷新核对四个请求。后台维护读取和空闲刷新不会产生用户命中或分项未命中。
- 核对归属于实际返回的旧决策或旧上游。例如旧 DIRECT 刷新为 SURGE，不一致记入 DIRECT；旧上游 A 刷新由 B 返回，不一致记入 A。新结果关闭乐观缓存时仍核对旧请求并保留有效的普通缓存；新响应 TTL 为零时核对后删除旧条目。
- 不一致率 = 不一致请求数 / 已核对请求数。无样本显示 `—`。失败、UNKNOWN、取消、generation 失效和淘汰前未完成的核对仍保持未核对状态，不记为一致。
- 总计及分项可靠性计数跨配置应用、缓存重建、上游配置变化和进程重启保留，直到手动清理缓存。升级前没有分项身份的累计计数只保留在总计，不倒填。
- 每个缓存以及跨解析池累计最多保留 1024 个具体统计身份，额外上游合并为「其他上游」，避免原始目标不断变化导致统计内存无界增长；该合并项不能当作具体上游设置开关。

状态 API 的 `cache.decision.groups`、`cache.response.groups` 和决策缓存 API 的 `stats.groups` / `response_stats.groups` 提供相同数据。`status.selective_cache_policies=true` 表示支持分项控制。远程管理沿用现有接口允许列表。

`/metrics` 添加 `decision_cache_by_decision_*{decision="DIRECT"}` 与 `response_cache_by_upstream_*{upstream="udp://192.0.2.53:53"}` 系列，包括 `entries`、`stale_entries`、`hits_total`、`misses_total`、`evictions_total`、`optimistic_hits_total`、`optimistic_compared_total`、`optimistic_mismatches_total`。总计指标继续保留。告警高频采样只读取总可靠性计数，不遍历缓存或复制分项表。
