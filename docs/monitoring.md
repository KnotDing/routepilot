# 大屏监控

在管理窗口左侧「总览 → 大屏监控」查看当前连接后端的 DNS 请求统计。页面沿用管理界面的主题、卡片、字体和配色，支持中英文、普通窗口、小窗口与 4K。点击「大屏模式」隐藏导航及软件更新提示，充分使用窗口空间；点击「退出大屏」或按 Escape 返回。此模式使用管理窗口内的布局，不要求浏览器或 WKWebView 的系统全屏能力。

## 页面内容

- **实时 / 历史：** 实时页三秒刷新当前累计数据，趋势来自后台持久采样。历史页支持最近一小时、六小时、一天、七天及自定义分钟范围，汇总指标、流向、策略、响应码和趋势使用同一个所选范围。
- **按源统计：** 来源 IP 展示在 DNS 请求流向图中，下方独立来源请求占比卡片沿用策略排行的比例条，展示流入请求数和占全部流入的比例；选择一个源后，所有图表及策略排行只统计该源。IPv4 映射的 IPv6 地址归一到同一 IPv4 源。NAT 后同一个可见 IP 不会被拆成虚构客户端。
- **请求概况：** DNS 流入、上游处理请求、已生成响应、正在处理、重启前未确认、平均处理耗时。
- **流向图：** 客户端源 IP → 本地记录、响应缓存、乐观响应缓存、真实 DNS 上游、Surge DNS、本机拒绝 / 空响应、未发往解析器。流带与流向占比仅以展示来源的已完成请求为基数，来源占比表以展示来源的流入请求为基数；不包含已隐藏的旧来源项。流带及两侧节点共用同一个请求数比例尺，悬停可查看数量和占比；展开精确数据可核对每条流向。流入源较多时展示请求最多的前十个源，其余来源按实际去向计数合并；占比表仍提供全部可展示来源。小窗口可横向滚动图形。
- **客户端策略流向：** 与 DNS 请求流向并列，显示客户端 → 实际命中的策略 / 策略组，使用相同时间范围、来源筛选、备注名称及请求数比例尺。后台从逐源策略计数生成最多十个主要源及十个主要策略，其余项按实际请求对合并；不会用来源占比乘策略占比推测流带。未记录策略和容量溢出单独标注，可展开查看每条显示流向的精确数量。手机端上下排列。
- **策略排行：** 分别查看规则命中的策略 / 策略组与最终策略，显示请求数及占全部已完成请求的比例。前十项之后合并为「其余策略」；展开明细可筛选并核对策略 → 最终策略 → 实际 DNS 处理去向。
- **速率趋势：** 实时模式最近六分钟、历史模式所选范围的 DNS 流入 / 响应速率，单位为请求 / 秒。按后台区间增量和实际观察时长计算；页面关闭后仍采集和持久化，重开页面可查询以前的趋势。超过 15 秒的采样间隔、服务退出或重启边界不生成确定速率，断开连线。较长范围最多展示 720 个趋势点，策略和流向汇总仍包含范围内全部桶。
- **占比：** DIRECT / SURGE / REJECT / UNKNOWN 分流决策与 DNS 响应码分布，均以全部已完成请求为分母。

## 统计口径

后台在客户端请求进入 Dispatcher 时计入流入，在生成 DNS 响应时计入完成。每条已完成请求只产生一个决策、一条接入到最终处理去向的流向，以及一条策略明细。所有图形和明细来自同一个加锁快照，不从有限的查询历史推算累计统计。

这里统计的是 **DNS 请求的处理路径和数量**。已生成响应不等于套接字写入成功或客户端已收到；真实 DNS 和 Surge DNS 去向表示请求调用的解析路径，并包括该路径返回错误的请求。响应缓存与乐观响应缓存单列，不误算作新上游请求。乐观响应缓存仅计入本次确实使用标记过期或失效旧值响应的命中；即使启用乐观模式，仍有效的正常缓存命中归入响应缓存。旧历史未记录这种区别，不倒填拆分。「上游处理请求」为最终真实 DNS / Surge DNS 去向的客户端请求数之和，不是网络交换次数。策略专用 DNS 可让 SURGE 决策使用真实 DNS；失败回退按最后采用的路径统计，不能由分流决策直接推断 DNS 出口。上游重试、后台刷新、健康探测、网络字节和后续应用流量不包含在图中。

UNKNOWN 是独立决策，不能与 SURGE 相加作为互斥分流比例。未执行 Surge 策略求值或结果没有策略名称时，保留「未记录策略」，不把 DIRECT / SURGE 决策补成虚构策略名称。全局最多保留 512 种策略 / 最终策略 / 去向组合；超出的新组合归入「超出明细容量」，不会丢失累计请求，也不冒充已知策略。

累计统计从首次启用此功能开始，不倒填旧查询历史或旧累计计数。每源最多保留 64 种策略流向（另有明确的溢出汇总），最多跟踪 512 个源（另有来源溢出汇总）；无法识别的源单独展示。升级前未采集来源的旧数据不显示在来源筛选、流向图或来源占比表，也不归入其他客户端；累计总数继续保留该部分；来源图与来源占比表的统计基数排除该部分，展示来源的占比合计为 100%。每五秒将累计检查点与区间增量通过同一个 SQLite 事务写入；增量合并进分钟桶并压缩保存，自动保留七天，空闲期仍记录零请求观察区间。事务失败不移动检查点，重试和重启不会重复计数。正常退出时等待请求结束并写入最终快照。异常退出可能丢失最后一次落盘之后的数据；落盘时仍在处理、重启后没有持久化完成证据的请求计入「重启前未确认」，不能据此宣称请求一定失败。此计数与已完成、处理中相加等于已记录流入数。配置重新应用及正常进程重启保留累计和历史数据，查询历史与域名日志开关不影响采集。按采样结束时刻归入分钟桶，表示统计观察区间而非逐请求日志时间；长时间采样中断的增量保留在恢复采样的桶，速率标为不可用。历史接收和完成可跨窗口，因此两者不必相等；处理中为窗口末的实际观察值。

实时页沿用管理窗口的三秒轮询，历史范围手动刷新；隐藏窗口时暂停页面轮询，后台统计继续进行。超过十秒未收到新快照显示数据过期。连接错误展示不可用；持久化失败会显示原因和重试入口；旧版后端缺少历史或来源能力时局部说明，保留已有实时管理功能。

## API 与指标

`GET /api/v1/status` 的 `dns_monitoring` 提供全局累计和含逐源流向的轻量来源列表（不附带逐源策略明细），以及有界的 `source_policy_flows` 客户端策略流向；`dns_monitoring_history` 说明历史能力、保留期及保存错误。`GET /api/v1/dns/monitoring?source=<IP>` 提供单源实时详情；`GET /api/v1/dns/monitoring/history?from=<RFC3339>&to=<RFC3339>&source=<IP>` 查询历史范围并提供同口径的 `source_policy_flows`，source 可省略。时间需对齐整分钟，最长七天；未采集的来源不可伪装为零请求。两个新接口仅加入远程中继的 GET 允许列表。旧版后端缺少客户端策略流向字段时，该图提示升级，不推测来源与策略的关联。

`/metrics` 同时提供 `dns_monitor_received_total`、`dns_monitor_completed_total`、`dns_monitor_unconfirmed_total`、`dns_monitor_in_flight`，以及按接入 / 处理去向、策略 / 最终策略 / 去向、响应码、决策划分的计数和处理时长 sum / count。`/metrics` 另提供带 source 标签的请求、流向和策略计数以及历史存储健康状态。

这些监控指标有独立统计起点，不能与启用前已有的旧累计计数混用。
