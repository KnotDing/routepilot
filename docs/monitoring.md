# 大屏监控

在管理窗口左侧「总览 → 大屏监控」查看当前连接后端的 DNS 请求统计。页面沿用管理界面的主题、卡片、字体和配色，支持中英文、普通窗口、小窗口与 4K。点击「大屏模式」隐藏导航及软件更新提示，充分使用窗口空间；点击「退出大屏」或按 Escape 返回。此模式使用管理窗口内的布局，不要求浏览器或 WKWebView 的系统全屏能力。

## 页面内容

- **请求概况：** DNS 流入、上游处理请求、已生成响应、正在处理、重启前未确认、平均处理耗时。
- **流向图：** 直接请求 / 透明拦截 → 本地记录、响应缓存、真实 DNS 上游、Surge DNS、本机拒绝 / 空响应、未发往解析器。流带及两侧节点共用同一个请求数比例尺，悬停可查看数量和占比；展开精确数据可核对每条流向。小窗口可横向滚动图形。
- **策略排行：** 分别查看规则命中的策略 / 策略组与最终策略，显示请求数及占全部已完成请求的比例。前十项之后合并为「其余策略」；展开明细可筛选并核对策略 → 最终策略 → 实际 DNS 处理去向。
- **速率趋势：** 当前页面最近六分钟的 DNS 流入 / 响应速率，单位为请求 / 秒。按相邻快照的累计计数差和实际时间差计算；第一个快照不计算速率，超过 15 秒的采样间隔断开连线。退出页面会结束本次趋势采样，后端累计统计继续保留。
- **占比：** DIRECT / SURGE / REJECT / UNKNOWN 分流决策与 DNS 响应码分布，均以全部已完成请求为分母。

## 统计口径

后台在客户端请求进入 Dispatcher 时计入流入，在生成 DNS 响应时计入完成。每条已完成请求只产生一个决策、一条接入到最终处理去向的流向，以及一条策略明细。所有图形和明细来自同一个加锁快照，不从有限的查询历史推算累计统计。

这里统计的是 **DNS 请求的处理路径和数量**。已生成响应不等于套接字写入成功或客户端已收到；真实 DNS 和 Surge DNS 去向表示请求调用的解析路径，并包括该路径返回错误的请求。响应缓存单列，不误算作新上游请求。「上游处理请求」为最终真实 DNS / Surge DNS 去向的客户端请求数之和，不是网络交换次数。策略专用 DNS 可让 SURGE 决策使用真实 DNS；失败回退按最后采用的路径统计，不能由分流决策直接推断 DNS 出口。上游重试、后台刷新、健康探测、网络字节和后续应用流量不包含在图中。

UNKNOWN 是独立决策，不能与 SURGE 相加作为互斥分流比例。未执行 Surge 策略求值或结果没有策略名称时，保留「未记录策略」，不把 DIRECT / SURGE 决策补成虚构策略名称。最多保留 512 种策略 / 最终策略 / 去向组合；超出的新组合归入「超出明细容量」，不会丢失累计请求，也不冒充已知策略。

累计统计从首次启用此功能开始，不倒填旧查询历史或旧累计计数。每五秒将变化的统计写入 SQLite；正常退出时等待请求结束并写入最终快照。异常退出可能丢失最后一次落盘之后的数据；落盘时仍在处理、重启后没有持久化完成证据的请求计入「重启前未确认」，不能据此宣称请求一定失败。此计数与已完成、处理中相加等于已记录流入数。配置重新应用及正常进程重启保留累计数据，查询历史与域名日志开关不影响采集。

页面沿用管理窗口的三秒轮询；隐藏窗口时暂停页面轮询，后台统计继续进行。超过十秒未收到新快照显示数据过期。连接错误展示不可用；旧版后端缺少监控字段时只降级监控页，其余管理功能继续可用。

## API 与指标

已有 `GET /api/v1/status` 的可选 `dns_monitoring` 字段提供完整快照，本地与远程中继复用相同接口，不新增写操作或远程允许列表项。

`/metrics` 同时提供 `dns_monitor_received_total`、`dns_monitor_completed_total`、`dns_monitor_unconfirmed_total`、`dns_monitor_in_flight`，以及按接入 / 处理去向、策略 / 最终策略 / 去向、响应码、决策划分的计数和处理时长 sum / count。这些监控指标有独立统计起点，不能与启用前已有的旧累计计数混用。

自动化验证及现场未覆盖范围见 [验收记录](acceptance.md)。
