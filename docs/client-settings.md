# 客户端设置

在客户端页面的「客户端列表」行内点击「编辑」，修改该源 IP 的备注名称及强制查询策略；不再单独维护配置卡片。编辑窗口固定所选 IP，支持清除该客户端的设置。已配置但暂时无请求或被统计列表淘汰的客户端仍显示在同一列表，缺失请求统计显示「—」，不会伪造为零。只支持具体 IPv4 / IPv6 地址，不支持 CIDR、通配符或主机名。IPv4 映射地址归一为 IPv4，重复地址禁止保存。最多保留 4096 项，备注最多 80 个字符。

- 自动：只保存备注，不覆盖原有查询策略。
- DIRECT：跳过策略求值，使用真实 DNS 路径，继续遵守全局的原始解析器保留设置。
- SURGE：使用 Surge DNS 路径。Fake-IP 健康 / 路由 / 发行门禁未就绪时返回 SERVFAIL，不退回真实 DNS。HTTPS / SVCB 保持空响应以引导 A / AAAA 查询，避免地址提示绕过 Surge。
- REJECT：返回 REFUSED，不查询上游，也不读取响应缓存。

客户端强制策略在查询格式及透明入口防环路校验、ANY 拒绝之后执行，优先于本地记录、AAAA 回落、always-real-ip、全局模式、域名覆盖和 Surge 规则。未匹配的客户端沿用原有优先级。查询记录明确标注客户端强制策略及 CLIENT-IP 规则；请求决策和实际 DNS 处理去向计入现有统计。

匹配基于后台实际看到的客户端源 IP。NAT 后同一个可见 IP 视为同一个客户端；IP 变化后从新 IP 的客户端行设置，旧配置可从旧行清除。备注名称仅影响显示，不作为匹配或统计身份。大屏历史使用当前备注名称，历史来源 IP 保持不变。

设置属于当前连接的后端，先校验并持久保存，再按现有异步配置应用机制生效；失败原因和重试入口显示在配置应用状态中。重启保留配置。它们位于 settings.dns.clients，跟随 DNS 分区备份 / 恢复。普通 settings PUT 保留当前客户端列表，避免旧版或其他窗口的设置表单覆盖独立编辑的客户端配置。

资源 API 为 GET / POST /api/v1/dns/client-settings，以及 PUT / DELETE /api/v1/dns/client-settings/{id}。字段为 id、ip、name、decision，decision 为空表示自动。接口沿用管理认证、写操作 CSRF 和允许列表受限的远程中继。旧后端缺少接口时，只禁用列表编辑入口，保留已有统计能力。

客户端列表的请求、决策、错误、最后活动及淘汰汇总每五秒保存至 SQLite 的 dns_clients 检查点，正常退出等待请求结束并保存最终值，配置重新应用和进程重启保留。无请求时不重复写入，保存失败显示在客户端列表及状态 API 的 storage_error，并通过 dns_client_statistics_storage_healthy 指标暴露；后台自动重试。最多保留 4096 个活跃统计地址，淘汰计数及累计汇总跨重启保留，已配置客户端仍可从同一列表编辑。异常退出可能丢失最近未落盘增量；旧版本未保存的客户端列表计数不倒填。

验证使用隔离配置、模拟 DNS 和浏览器，不代表已在生产客户端或真实 IPv6 网络路径验收。
