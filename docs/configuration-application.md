# 配置按模块应用

配置仍作为完整文档校验、持久化，保存完成后立即返回；单个后台任务计算实际差异并更新受影响的模块。无需另存多套 A / B 配置。保存成功与运行应用完成仍分开显示，失败保留原因和重试入口。

## 设置项与应用范围

| 设置项 | 应用方式 | DNS 与 BGP 的影响 |
| --- | --- | --- |
| 日志级别、事件容量 | 更新日志级别 / 事件保留参数 | 不重建 DNS，不重启 BGP |
| 内存查询记录、保留域名、记录容量 | 原地调整查询记录缓冲区 | 不重建 DNS，不重启 BGP；关闭时清空已有查询记录，缩容保留最新记录；旧代记录不能在清理后回填 |
| 探测主机名 | 单独启停后台 PTR 任务 | 不重建 DNS，不重启 BGP；关闭时取消查询并清除探测名称，开启只为未备注客户端探测 |
| 截断探测主机名的域部分 | 读取显示配置，保留完整探测缓存 | 不重建 DNS / BGP，不重启 PTR 任务；只截断探测名称，备注和 IP 身份不变 |
| 客户端备注、强制查询策略 | 替换只读客户端策略快照，按需更新主机名探测任务 | 不重建 DNS，不重启 BGP；新请求使用新策略，已开始处理的请求可按此前选定策略完成 |
| AAAA 回落 | 原地替换回落配置 | 不重建 DNS，不重启 BGP |
| 分流模式、域名覆盖、本地 Hosts | 更新策略 / 本地记录，按原有规则失效相关缓存与 Fake-IP 门禁 | 不重建 DNS，不重启 BGP |
| 通知筛选、异常阈值、Webhook、Surge 异常重启 | 更新当前配置，监控与通知读取生效值 | 不重建 DNS，不重启 BGP |
| 自动更新、更新源、远程后端连接、界面主题 | 更新配置，原有调度或页面读取生效值 | 不重建 DNS，不重启 BGP |
| 管理认证、访问白名单、反向代理 | 更新管理安全模块 | 不重建 DNS，不重启 BGP |
| 管理监听地址、TLS 证书 / 私钥 | 预检后重新绑定管理监听 | 不重建 DNS，不重启 BGP；失败沿用原有恢复流程 |
| DNS 监听、上游、出口、策略专用 DNS、透明入口及拦截目标 | 重建 DNS 运行实例与对应监听 / 解析资源 | 保留未改变的 BGP speaker / 邻居会话；健康绑定路由按下方规则处理 |
| 决策 / 响应缓存设置、Surge CLI / API / DNS / Fake-IP 网段、健康检查参数 | 重建依赖这些参数的 DNS / 策略 / 健康运行实例 | 保留未改变的 BGP speaker / 邻居会话；缓存 generation、TTL、客户端隔离、累计统计沿用原有保证 |
| BGP 启停、ASN、Router ID、监听端口、全局定时器及路由容量 | 只重建 BGP 模块 | DNS 监听、分流器及缓存继续运行 |
| BGP 邻居列表及单个邻居参数 | 在现有 speaker 上同步邻居 | 不重建 DNS 或整个 BGP；需要时只调整相应邻居会话 |
| 手动路由及属性、手动路由分发方式 | 在现有 speaker 上增删或更新受影响前缀；分发方式改为 API 时热替换路由器 API 后端，改为 Static 时转为外部声明 | 不重建 DNS；BGP 仅为手动路由启用且全部改出 BGP 时才关闭 BGP 模块 |
| 路由订阅计划 / URL | 更新调度配置；导入的路由沿用上述差量应用 | 不因计划本身重建 DNS 或 BGP |
| Fake-IP 下一跳、路由后端和静态声明确认 | 先关闭发放门禁并等待必要的旧 TTL，再更新路由声明 | 通常保留 DNS 和 BGP；启用 / 停用 BGP 的后端切换仍需启动 / 关闭 BGP 模块 |
| 自动探测的 Surge VM IPv4 地址 | 留空 IPv4 下一跳时，每 30 秒最多探测一次；地址变化时按 TTL / 宽限期排空后更新路由 | 不重建 DNS 或 BGP；探测失败暂停新 Fake-IP，静态网关路由需要对新地址重新确认 |

## 必要的跨模块依赖

- `DNS.source4/source6` 也用作对应地址族的 BGP 邻居本地绑定地址。修改实际被启用邻居使用的源地址时，需要同时重建 DNS 和 BGP；没有该地址族的邻居时，不因此重启 BGP。
- DNS 停止接收前关闭 Fake-IP 发放并拒绝旧 lease 写回，等待正在写回的响应结束。暂时撤回依赖 Controller / DNS 健康的受管路由；已发放 Fake-IP 的必要路径按原有 TTL / 宽限期保留。DNS 不可用期间，未绑定健康的手动路由保持在现有 RIB 中。
- 保留 BGP 会话不等于所有前缀保持发布。监听不可用、健康变化、静态确认失效或下一跳改变时，路由安全门禁仍可撤回相关前缀；重新就绪后再由原有状态机发布，不宣称网关 RIB / FIB 已安装。
- 同一次保存同时修改多个分区时合并依赖：例如同时修改 DNS 上游与手动路由，会重建 DNS、差量更新路由，保留 BGP speaker；若还修改 BGP 全局 ASN，则必须重建 BGP。
- 只调整非 DNS 模块时，不再打开 PF 设备预检；实际重建透明 DNS 时仍先验证 PF 访问权限，失败保留运行中的服务。

## 失败恢复和验收边界

DNS 新配置启用失败时，在保留的 BGP 实例上尝试恢复旧 DNS 配置，不为了恢复 DNS 重新创建未变更的 BGP。新配置及恢复均失败时保留明确的应用错误；最终退出仍负责清理所持有的路由资源。只有最后成功应用的配置写入运行检查点，已保存的目标配置不因失败被丢弃。

自动化验证使用临时数据库、本机随机端口、模拟 DNS 和隔离的真实 GoBGP 邻居。检查会话建立时间在 DNS / 缓存 / 隐私变更前后不变，独立手动路由保留，DNS 监听失败后恢复与重试不替换 BGP，隐私关闭清理记录并拒绝旧代写入，记录调整与请求并发无竞争。此范围不代表已更新现用 App / 后台，也不代替真实网关、PF、LAN / IPv6 或长期可用性验收。
