# v0.5.1 发布评估

## 结论

发布 **v0.5.1**。当前构建可交付使用，暂不升至 1.0.0。主要依据是实际网络与特权升级的验证范围尚未完整覆盖，而非仅以测试数量判断稳定性。

## 本次完成的检查

| 项目 | 结果与验证范围 |
| --- | --- |
| 前端回归 | 55 项通过，包含语言设置位置、侧栏分流模式的真实请求、退出/后端切换入口和移除重复横幅 |
| Go 服务 | 全部包的 race 测试及 go vet 通过；涵盖 DNS 分流、缓存持久化与乐观刷新、配置应用、认证和中转隔离 |
| BGP | 真实 GoBGP 进程通过 loopback 高端口建立会话、接收发布与撤销；这些结果不能代替外部网关的 RIB/FIB 验证 |
| 页面布局 | 15 个页面、12 个设置分类在 1440、1120、390 像素宽度下通过检查；远程更新说明结构及横排按钮正确 |
| 原生动画 | 隔离检查实际观察到 5 种心跳图像和 15 种连接旋转图像；离线保持静止，图像固定 18×18 且使用系统模板着色 |
| 安装包 | Swift/AppKit App、内嵌 Go 服务、离线 Markdown 查看器、DMG、ZIP 和后台归档均成功构建并通过本机代码签名检查 |

测试与预览使用隔离数据、loopback 或 API 模拟，不更改正在运行的 DNS/PF、Surge 或网关配置。

## 升到 1.0 前的关键验证

1. IPv6：实际 macOS PF 入口、原始目标恢复与独立网关 WAN 绕行路径。现有 IPv6 DNS/BGP/规则构造自动化覆盖并不等同于这条真实链路已验收。
2. 升级：标准 root launchd 后台的远程升级，以及 App 更新助手的真实成功/失败恢复、重新连接与数据迁移兼容性回归。当前升级模块没有专门的 Go 自动化测试，页面的模拟检查不能替代执行文件替换与回滚验证。
3. 稳定性：真实 Surge、外部 BGP 网关与透明 DNS 的持续运行和故障注入，确认服务重启、网关/Mac 丢失后的流量恢复及路由撤销。

既有实测证据和部署限制见 [验收记录](acceptance.md)、[透明 DNS 实测记录](phase-2-docker-evidence.md) 与 [远程管理](remote-management.md)。其中历史记录不视为本次重新执行的实测。
