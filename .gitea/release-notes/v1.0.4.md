# RoutePilot v1.0.4

本次正式版汇总 **v1.0.3 以来、v1.0.4-beta.1 至 beta.28** 的变更，按最终功能归并重复改进和修复。

## 大屏监控与七天历史

- 新增大屏监控，展示 DNS 请求概况、流入 / 响应速率、分流决策、响应码、策略 / 最终策略排行和平均处理耗时，支持中英文、深浅主题、4K 大屏及手机布局。
- 提供「来源 → 实际 DNS 处理去向」与「客户端 → 命中策略 / 策略组 → 最终策略」两张流向图，使用实际请求关联和共享比例尺。点击流带可高亮，并固定显示精确请求数与占比；来源名称可点击切换备注 / IP，长名称完整换行，小流量节点不再重叠。
- 支持实时与历史切换，查询最近一小时、六小时、一天、七天或自定义范围。后台在页面关闭期间继续采集，每五秒保存检查点，按分钟保留七天历史；配置应用与正常重启后继续查询。
- 支持来源、DNS 处理去向、策略 / 策略组、最终策略、域名、响应码六项组合筛选，实时与历史使用相同条件。来源和域名排行支持点击筛选；独立域名统计提供前一百名及精确的其余数量，不再受组合明细容量限制。
- 新增监控卡片显示偏好和敏感数据保护，隐藏 IP、备注、后端名称 / 地址、策略和域名，筛选、提示与明细同步保护。App 和浏览器分别保存展示偏好；这些选项只改变显示，不修改后台统计或查询策略。

## 客户端管理

- 可直接从客户端列表行编辑备注和强制查询策略，选择自动、DIRECT、SURGE 或 REJECT；已配置但暂时没有请求记录的客户端仍可编辑，无统计时显示未知。
- 设置以后台实际观察到的源 IP 匹配，支持 IPv4 / IPv6 并归一 IPv4 映射地址。备注优先用于客户端列表与监控显示，策略和历史身份仍按 IP 区分；NAT 后共享源地址的设备不会被虚构拆分。
- 客户端请求数、分流决策、错误数、最后活动和淘汰汇总持久化，配置应用与后台重启后继续累计。保存失败显示原因并自动重试；备注和策略支持 DNS 配置分区备份 / 恢复。
- 「日志与隐私」新增默认关闭的主机名探测，由当前后端在后台反向查询未备注客户端，带超时、缓存和失败重试。显示顺序为手工备注、探测名称、IP；结果不写入备注，也不改变策略。
- 可将探测名称的域部分截断，如 `device.example.local` 显示为 `device`。只影响探测名称，手工备注不变；关闭后可立即恢复完整名称。

## 普通缓存、乐观缓存与可靠性

- 决策缓存、响应缓存、乐观决策缓存和乐观响应缓存分别提供总开关及分项控制。决策按 DIRECT / SURGE / REJECT 等类型管理，响应按全局、策略主 / 备用及已观察的原始 DNS 上游管理。
- 关闭普通缓存总开关或分项时，同时关闭并禁用对应乐观缓存；重新启用普通缓存不会自动开启此前关闭的乐观缓存。设置收起后保留分项选择，旧配置沿用兼容默认值。
- Surge DNS 响应支持独立普通 / 乐观缓存及统计，涵盖普通 SURGE、客户端强制 SURGE 和策略 DNS 的 Surge 回退路径。保持客户端与完整查询隔离，命中仍遵守健康、路由、Fake-IP 范围及 TTL 门禁；旧 Fake-IP 内容不跨后台重启恢复。
- 决策缓存页与查询记录页显示分项条目、命中、未命中、淘汰、待刷新及乐观可靠性统计。已核对、不一致和不一致率跨缓存重建与重启保留，直到手动清理；不一致率以已核对请求为分母，失败或未完成刷新不记为一致。
- 监控分别标记普通响应缓存与实际使用旧值的乐观响应缓存，避免误算成新上游请求，页面、状态接口及指标保持一致。

## 配置应用、路由与 Surge

- 配置按实际依赖更新模块：DNS、缓存或健康参数变化时保留未改变的 BGP 邻居会话；BGP 全局参数变化时 DNS 继续运行。BGP 邻居与手动路由按差异更新，未绑定健康的手动路由在 DNS 暂停期间保留。
- 日志级别、查询记录开关、域名保留、逐条查询记录容量、客户端备注 / 策略、主机名探测等支持热更新。关闭查询记录清空已有逐条记录，缩小容量保留最新记录；无需重启 DNS 或 BGP。
- DNS 新配置启用失败时尝试恢复原配置，保留未改变的 BGP 实例；持续显示应用错误并提供重试。保存完成与后台应用完成仍分开反馈。DNS 源地址同时用于 BGP 邻居绑定等必要依赖，仍会同步更新相关模块。
- Surge IPv4 下一跳改为选填：留空时由当前后端探测 Surge VMNET 的 `self-ip`，手填地址优先。字段旁显示地址、待应用状态或错误；每 30 秒最多探测一次，旧 CLI 不支持或增强模式未运行时可手填。
- 自动地址变化或探测失败时暂停新的 Fake-IP 响应，按已有响应的 TTL / 宽限期排空后更新或撤回路径。外部静态路由仍由用户配置，确认绑定当时的自动地址，变化后需按新地址重新确认。
- 静态 DNS 拦截的网关路由确认移到「DNS 拦截」页，点击按钮立即保存；确认后置灰，相关配置变更使确认失效后可再次确认。「Fake-IP 网段」改为单行输入，多个网段用中英文逗号分隔。

## 多后端窗口与界面

- 状态栏「打开管理窗口」可选择本地或已保存的远程后端；仅有本地时直接打开。支持同时打开多个管理窗口，分别控制不同后端；同一目标复用窗口并从最小化恢复，保留未保存编辑。
- 窗口标题显示后端名称和地址，各窗口独立维护后端选择、会话、CSRF、回调、可见性和页面状态。登录或保存结果返回来源窗口，切换后端只影响当前窗口；本机 App 偏好继续共享。
- 远程请求和后台操作轮询绑定所选后端地址。连接地址被其他窗口改动时，旧窗口要求重新连接，防止请求转向不同目标；旧版后端缺少可选功能时局部降级。
- 侧边栏支持完整、仅图标、完全隐藏和左侧边缘悬浮展开，状态保存在当前管理界面。收起、展开、隐藏和固定按钮集中在左下角；两张监控图按宽度并列或上下排列，保持文字字号、真实请求比例与自然高度。

## 更新、会话恢复与通知

- 检查更新只读取版本和说明，确认安装后才下载；本机安装窗口和远程管理显示实际字节进度。缺少总大小或旧助手不提供进度时显示不确定状态；已校验的下载缓存仍可复用。
- 「保存设置」「立即检查更新」及检查后出现的安装 / 升级按钮放在同一底部操作行，管理本机、浏览器与远程后端的布局一致。
- 后台重启后，已打开的 App 管理页面可使用已保存凭证恢复本机会话并更新 CSRF，短暂失败自动重试；主动退出保持退出，没有有效保存凭证时仍需登录。
- 远端升级完成但 App 等待确认、稍后重启或重启失败时，可经单独确认「强制重启远程 App」。此步骤只重启图形 App，不再次重启网络后台；重复操作不会触发多次重启，已手动重开的 App 不会被误关。该操作可能丢弃远端未保存编辑，需远端支持相应接口。
- 远程后台已更新、仅 App 待重启时使用普通提示；等待期间降低轮询频率，实际重启继续显示进度。
- 新增缓存不一致率、突发 DNS 请求量和持续高请求量告警，可独立选择并调整阈值，通知详情显示实际数值。后台独立采样，告警不直接改变分流、路由或触发 Surge 重启。
- 本机通知与声音设置移至状态栏「应用偏好 → 本机通知设置」。管理页面继续配置后端异常通知与 Webhook；App 可在窗口关闭后继续观察本机及已登录远程后端，浏览器通知仍需页面保持打开。

## 数据正确性与资源开销修复

- 修复旧来源统计共享数据导致历史保存失败，以及组合明细满容量后重启出现「监控请求维度计数回退」的问题。恢复和合并保留具体明细，溢出单独汇总；从最后完整检查点继续保存，无需清空历史，成功后清除错误提示。
- 未采集来源的旧请求不再归入客户端或展示来源分母；客户端策略图排除未记录最终策略的请求及其分母。未知策略、其余项与容量溢出保持独立，不用边际比例或有限查询记录推造关联。
- 修复三层流向图比例尺、中间节点对齐、长名称、小流量文字重叠及调整窗口时字体缩放问题。历史读取失败时保留可用的实时视图；停机或采样缺口不绘制虚假连续趋势。
- 减少中文菜单翻译与正则构造、关闭查询记录时的无用格式化、DNS 答案重复格式化和无关状态快照复制；高频告警采样读取累计数，不遍历全部缓存。默认 worker、队列和缓存容量未为压测提高。

## 升级与数据说明

- 安装包面向 **Apple Silicon、macOS 13 及以上**。已有安装请从「设置 → 软件更新」完成 **App、管理页面、CLI 和网络服务**的完整升级；手动拖放替换 App 不保证常驻后台同步更新。
- 新增主机名探测、名称截断及乐观缓存按各自默认值 / 既有配置生效；静态网关路由仍由用户配置和确认。
- 监控统计描述 DNS 请求数量及处理路径，不是网络字节或后续上网流量。域名聚合独立于逐条查询记录 / 域名日志开关；展示脱敏不会删除后台数据。
- 历史保留七天；旧版本未采集或未保存的数据不倒填，缺失组合关系明确标为不可用。异常退出仍可能丢失最近尚未落盘的增量。
- 路由发布、包完整性和自动化检查不代表网关已安装路由，也不代替真实 LAN / IPv6 路径或长期运行验收。

## English summary

This stable release consolidates all 28 beta releases since v1.0.3:

- Add live monitoring and seven-day persistent history, request-based DNS and three-stage client/policy flow diagrams, exact ribbon selection, six combined filters, independent domain rankings, configurable cards and display privacy.
- Edit client names and forced DNS policies in the client list, persist client statistics, and optionally discover PTR hostnames or show only their device-name portion. Matching and statistics retain the observed source IP identity.
- Control ordinary and optimistic caches independently by decision and upstream, including Surge DNS responses. Preserve client isolation, routing/TTL safety and persistent per-item reliability counters; failed comparisons never count as matches.
- Apply configuration by dependency: hot-update logging/privacy and client settings, preserve unchanged BGP sessions during DNS updates, keep DNS running during BGP-only changes, and recover failed DNS activation without replacing an unchanged speaker.
- Detect the Surge VM IPv4 next hop when the field is blank, with explicit addresses taking priority. Drain issued Fake-IP answers before replacing paths; static gateway routes require renewed confirmation after address changes. Enter Fake-IP prefixes in a single comma-separated field.
- Open independent management windows for local and remote backends, isolate sessions and callbacks, bind remote requests to the selected address, restore saved local sessions after backend restarts, and offer expanded/icon-only/hidden navigation.
- Download updates only after confirmation, show actual progress and consistent action placement, and separately confirm remote graphical App restarts after an upgrade without restarting the network backend again.
- Add configurable cache-mismatch and DNS-volume alerts, move local notification preferences to the App menu, fix monitoring checkpoint recovery and flow-layout errors, and reduce repeated formatting and snapshot work.

Upgrade the complete App and network service through Settings → Software update. Packages target Apple Silicon on macOS 13+. Missing historical data is not reconstructed; display privacy does not erase stored aggregates. These checks do not establish external gateway installation or live LAN/IPv6 acceptance.
