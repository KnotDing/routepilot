## 保存完成立即返回，后台应用配置

- 设置、条目增删改、批量删除、备份恢复、路由后端与 URL 规则更新在校验并成功落盘后立即返回；服务重启、路由调整和安全等待在后台串行执行。
- 页面单独显示后台应用进度和失败原因，支持重新应用；失败时保留已保存的配置及最后成功的运行配置。
- URL 预览、Surge Hosts 导入、规则测试、探测、缓存清理与检查更新立即返回任务状态，完成后展示实际结果。
- 单独修改 AAAA 回落热更新，无需重启 DNS 或 BGP。其他 DNS 重建保留适用的决策快照和原 TTL。

## 决策与响应缓存支持独立的乐观刷新

- 设置 → 缓存新增“乐观决策缓存”和“乐观响应缓存”，默认关闭。
- 开启后，确认 Surge 配置或外部资源更新时保留旧缓存。下次命中先响应，再在后台刷新；成功后替换，失败时保留旧值并稍后重试。
- 后台刷新合并同一条目的并发查询并限制任务数量；手动清理后，旧刷新任务不能重新写回。
- 决策的待刷新标记随缓存持久化；UNKNOWN 和求值失败不替换旧决策。关闭乐观模式后恢复立即失效行为。
- 响应缓存覆盖默认与策略专用上游池，遵守原 DNS TTL，不跨重启保留。SERVFAIL、REFUSED 等刷新失败不会覆盖旧响应。
- 独立配置的读取失败、策略组切换失效规则，以及手动清理、TTL 和容量限制仍然生效；Fake-IP 仍需通过路由和健康检查。
- 修复 Surge IPv6 配置短暂读取失败被误认为有效配置更新的问题；读取失败仍停止条件 AAAA 拦截。
